# Синтезис / Synthesys

**Открытый модульный домашний компьютер на ESP32-S3**

> Не скрывать сложность — возвращать её под контроль пользователя.

Синтезис — проект многопроцессорного домашнего компьютера: CPU, Storage, Video, Audio, HID и будущие устройства представляют собой **самостоятельные процессорные модули**, каждый со своей прошивкой и локальной памятью. Центральный CPU исполняет пользовательские программы и координирует систему, но **не формирует видеокадры, не синтезирует аудиопоток и не копирует ресурсы из Storage в память периферийных модулей** при штатной прямой загрузке.

## Основные принципы

1. **Локальная память:** каждый модуль использует собственную RAM/PSRAM; общей RAM между платами нет.
2. **Интеллектуальная периферия:** Video рисует текст, примитивы, тайлы, спрайты; Audio синтезирует и микширует звук. CPU отправляет высокоуровневые команды.
3. **Прямые загрузки:** CPU открывает файл, разрешает диапазоны Storage и организует передачу Storage ↔ любой модуль *без промежуточного копирования данных через RAM CPU*. CPU может синхронно ждать завершения или обслуживать события.
4. **Одна общая HESS:** адресная SPI-шина с временным владением любым допущенным модулем, индивидуальным выбором получателя и аппаратной защитой от одновременных драйверов.
5. **Сборка своими руками:** базовый эталон — перфоплаты, провод МГТФ внутри модулей и короткая магистраль из витых пар на объединительной плате. Не предполагается горячая замена.
6. **Открытые спецификации:** разделяем проверенные решения, проектные предложения и испытания.



## Обязательная минимальная конфигурация: Synthesys-5

**CPU + Storage + Video + Sound (Audio) + Input (HID) должны работать одновременно.** Проект нельзя считать полноценным компьютером, пока не выполнен [приёмочный профиль пяти модулей](docs/acceptance-five-modules.md): игра ≥256×192 с 50 обновлениями/с, стабильный экран ≥50 Гц, 4 голоса звука, реальный ввод PS/2 **или** USB, прямые передачи ресурсов, отсутствие коллизий HESS и длительные нагрузочные испытания. Это **требования**, а не подтверждённые измерения.

## Аппаратный старт: HESS-40 и CPU

Согласованная последовательность: **CPU USB monitor → Storage/SD → загрузка маленькой ОС и файлового коммандера в терминале ПК → Video → Input (PS/2 или USB Host) → Sound**. Это порядок реализации; **минимальный готовый компьютер по-прежнему состоит из всех пяти модулей**. Односторонний ключевой разъём HESS-40 (2×20) несёт питание +5 V/GND, SPI, CS/GRANT, reset и управление backplane. Текущая распиновка — **проект для проверки**, не утверждённая производственная схема.

## Статус

**Ноябрь 2026 — согласованная концепция, инженерный проект для P1, аппаратные измерения ещё не выполнены.**
HESS v1, распиновка слота, адресное декодирование, буферизация и кодек протокола описаны как **проект для проверки**, а не как испытанная совместимая шина. Первая реализация — стандартный SPI 1-bit, 100 кГц → 1 → 4 МГц с проверкой. QPI и высокая частота являются экспериментальными расширениями, а не требованиями к P1.

Спецификация не является утверждённой схемой для изготовления PCB: до монтажа проверить маркировку ESP32-S3 N16R8, GPIO, доступность SPI slave, логику Hi-Z, электрические уровни, источники питания и тестовые сценарии.
