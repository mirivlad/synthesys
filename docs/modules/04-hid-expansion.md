# HID и система расширений

## HID

HID — самостоятельный модуль опроса клавиатуры/мыши/джойстика. Драйверы локальные, а CPU получает **события** с кодом, модификаторами, состоянием, timestamp/sequence. CPU не обязан опрашивать каждую клавишу отдельно или самостоятельно декодировать PS/2.

Для **минимальной полной системы** обязателен **PS/2 ИЛИ USB Host HID** клавиатурный ввод. PS/2 — наиболее простой первый вариант, с согласованием 5-вольтовых pull-ups/open collector к 3,3 В. USB Host — равноправная альтернатива, но требует OTG-порта, VBUS с защитой и учёта разделяемого PHY USB-Serial-JTAG. ESP-IDF имеет официальный [HID Host example](https://github.com/espressif/esp-idf/blob/master/examples/peripherals/usb/host/hid/README.md). Мышь/joystick желательны, однако не обязательны для первой 5-модульной демонстрации.

События буферизуются; `ATTN_N` сообщает CPU о наличии события, которое считывается очередной HESS-транзакцией.

## Модули третьих сторон

Новый модуль описывает:
- `slot_id` физический (read-only strap/EEPROM);
- `device_id` логический (одна плата может иметь несколько функций);
- `device_type`, firmware/protocol versions;
- `features` (SPI_MASTER, SPI_SLAVE, BULK_READ, BULK_WRITE, IRQ_EVENTS, BUFFERED_RESOURCES);
- буферы, допустимый размер кадра и предельную тестовую частоту интерфейса;
- набор команд и коды ошибок.

Модули не должны предполагать, что устройство Storage всегда на slot1, а Video всегда на slot2. CPU проводит обнаружение при boot и сопоставляет устройство с подходящим драйвером. Горячая замена в P1 **не поддерживается**.

## Границы доверия

HESS — внутренняя физическая шина доверенных модулей. Нет изоляции злонамеренного устройства. CPU выдаёт полномочия на Storage и ограничивает прямые передачи, но это не аппаратная криптографическая защита. Для подключения внешних клиентов или сетевого модуля необходимы дополнительные проверки команд/буферов.

## Приёмка Input

Независимо от выбранного PS/2 или USB: локальная **FIFO ≥256** событий с монотонным sequence, `keydown` / `keyup`, timestamp, overflow counter и `ATTN_N`. Отложенное обслуживание CPU после длинного grant не должно потерять события или заморозить сам Input. Цели измерения до реакции игры: p95 ≤50 мс, p99 ≤80 мс; 0 неучтённых потерь. Чтение input packets должно поддерживать batch, чтобы не загромождать HESS мелкими транзакциями. [Пятимодульная приёмка](../acceptance-five-modules.md).
