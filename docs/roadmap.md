# План разработки M0–M8

| Этап | Результат | Приёмка |
|---|---|---|
| **M0** | Уточнены devkit, pinout, схемы OE, разъёмы и питание | netlist reviewed, никаких опасных состояний на reset |
| **M1** | CPU + Storage, обычный SPI 1-bit, PING/GET_INFO | 10 000 успешных циклов при 100 кГц → 1 МГц без CRC/timeout |
| **M2** | SDMMC standalone, FAT32 на CPU | raw LBA read, `boot.ini`, проверка фрагментированного файла |
| **M3** | Три платы, аппаратный OWNER/TARGET/grant | CPU → test-peer и test-peer → Storage при отключенном CPU master driver |
| **M4** | Универсальная прямая передача | 64 КиБ Storage → test-peer с CRC/сбоями и восстановлением |
| **M5** | Video standalone + Video ← Storage | цветные полосы, текст, примитивы, спрайт из SD напрямую |
| **M6** | Audio standalone + Audio ← Storage | I2S tone/mixer, sample load, no underruns в норме |
| **M7** | HID и рабочая оболочка | полноценный ввод, загрузка программы, команды Video/Audio |
| **M8** | ELF/ABI + демонстрация | запуск приложения без перепрошивки, собственные assets и звук |

## Дальше

1. Проверить 8 полноценных слотов, суммарный power budget, длинные жгуты, температурную стабильность.
2. Перейти от SPI 1-bit к 4-bit/QPI **только после подтверждения slave/master PHY и буферизации**.
3. Выпустить KiCad-проекты (backplane + адаптер слота), автоматизированную host-side диагностику и подробное руководство для повторения.
4. Создать BASIC/SDK, видео- и аудиодемо, игры. Приоритет — полезная работающая система, не максимальная частота шины.

## Порядок при ограниченном времени

Самый опасный вопрос — M3: mastership на общей шине, выключение OE и корректная работа ESP32-S3 в slave/master. Рекомендуется **протестировать M3 до сборки полной VGA платы**. Если на M3 обнаружен аппаратный тупик, пересмотреть HESS hardware, не переходить слепо на двушинную архитектуру.
