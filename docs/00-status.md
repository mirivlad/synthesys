# Статус, уровни достоверности и область применения

**Дата редакции:** 17.11.2026. **Состояние:** архитектурный проект, перед аппаратной валидацией.

## Согласованные принципы (концептуально)

- **CPU, Storage, Video, Audio, HID** — отдельные ESP32-S3 N16R8 с собственным исполняемым кодом, RAM/PSRAM.
- Нет единой ОЗУ, общесистемной когерентности кэшей, совместного адресного пространства.
- **CPU координирует работу и управляет файловой системой.** Video самостоятельно отрисовывает экран из локальных ресурсов, Audio генерирует/микширует звук, Storage обслуживает SD по секторам, HID обрабатывает ввод.
- Ресурсы передаются напрямую между произвольными модулями, если один из них может быть SPI-master, а второй SPI-slave. CPU **разрешает** передачу и знает её статус, при необходимости ждёт её окончания. Передача через память CPU возможна только в диагностическом fallback.
- Единая общая **HESS**: адресный выбор получателя + отдельный выбор владельца, арбитраж CPU, аппаратный запрет конкурирующих драйверов; на старте SPI 1-bit, потенциально QPI после отдельной проверки.
- Первая сборка P1 — макетные паяные платы, короткая магистраль из витых пар, МГТФ внутри модулей. Питание только при отключённом USB/backfeed-контуре, без горячей замены.

## Что не утверждается

Этот репозиторий **не является комплектом проверенных схем для непосредственной пайки**. Нет результатов измерений фронтов, skew, согласования, питания и работы SPI master/slave на общей магистрали. Псевдокод не является прошивкой. Никакая заявленная скорость не считается достигнутой.

## Версии

- Исторические материалы v1.0 (2025), прототип v0.2 и рабочее ТЗ v0 сохранены в `legacy/`.
- Восстановленный, но позже отвергнутый проект **HESS-C + HESS-D** не является текущей архитектурой.
- Текущий архитектурный профиль назван **HESS v1 draft**. Это не бинарная совместимость с ранним CRC8 / 0xAA.
- Требования безопасности (Hi-Z, последовательность перехода владения, защита питания) обязательны до сборки P1.

## Подход к разработке

Никакой ветки «обещанные 80 МГц». Каждое решение проходит: спецификация → двухплатный тест → осциллограммы/логические трассы → трёхплатная прямая передача → проверка на 5 устройствах. Результаты в `docs/tests.md`.

## Минимальная проверка Synthesys-5

**Пятимодульная система — единственный критерий минимальной полной работоспособности**, а стенды из 2–3 карт — лишь подготовительные. Обязательны CPU, Storage, Video, Sound (Audio), Input (HID; PS/2 или USB). Все пять должны быть активны одновременно. Требуются воспроизводимые результаты производительности игрового класса — в сравнении с практическим уровнем ZX Spectrum — и отсутствие конфликтов за HESS. Ссылаться на [строгие требования](acceptance-five-modules.md) и [тесты](tests.md). Не объявлять FULL PASS без 60 мин стресс-теста и 24 ч burn-in.
