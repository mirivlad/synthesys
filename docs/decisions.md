## Критические вопросы перед пайкой

1. Какие **точно** devkit ESP32-S3 N16R8 есть в наличии и каковы их настоящие электрические схемы?
2. Могут ли SPI2/3 работать в нужной master/slave-конфигурации одновременно с SDMMC / LCD_CAM / I2S на выбранных GPIO без конфликтов? Что показывает M3?
3. Как выглядит точная логическая схема CPU OWNER/TARGET→дешифратор→GRANT_N/CS_N→buffer OE и XFER gating, включая reset?
4. Как выбранный slave подтверждает готовность для очередной DMA-транзакции без гонки CS?
5. Как обеспечить safe fallback, если арбитр CPU перезагрузился, пока peer был master?
6. Какой точный слот/ключ/полярность/нумерация и земля между проводниками?
7. Какая доступная мощность общей 5V системы при запуске пяти устройств?
8. Где проходит граница полномочий стороннего модуля к LBA и видеопамяти?

## Не считать текущим

- Две независимые шины HESS-C + HESS-D из обсуждения 16.11: **отменённое архитектурное предложение**, не смешивать с текущим pinout.
- CAN для управления, Storage-постоянный master, DMA в память CPU, общая VRAM: **не текущая модель**.
- Старое `HESS_FRAME` вместо новой gated `XFER_N`, старый CRC8, 80 МГц «гарантированно»: **историческое**, не обязательное требование.

## ADR-015: Synthesys-5 является минимальным полным ПК

**ACCEPTED (требование):** CPU, Storage, Video, Sound (Audio), Input (HID) — пять автономных ESP32-S3 и обязательная одновременная работа. Стенд из меньшего количества плат нужен только для разработки. **Input принимает PS/2 или USB Host HID**; оба одновременно не обязательны. Базовое качество — воспроизводимый игровой 2D-демо уровня как минимум практических возможностей ZX Spectrum: ≥256×192, 50 обновлений/с, четыре звуковых голоса, реальный input без потери событий, безопасные direct transfers. **Никаких объявлений готовности до пяти-модульного стресс-теста**. Цифры/методология — [acceptance-five-modules.md](acceptance-five-modules.md).

## ADR-016: Bounded grants и регулярное обслуживание Input

**ACCEPTED (требование), аппаратная реализация НЕ проверена:** peer-to-peer bulk transfers выполняются конечными короткими квантами с возвратом CPU между ними, чтобы обслуживать Input, Video и Sound. Общая `ATTN_N` не прерывает уже идущую SPI-транзакцию; арбитр обязан ограничить её длительность и восстановить владение. Программное «первое пришёл — первый обслужен» без deadline/условия fairness для полной пяти-модульной системы недостаточно.
