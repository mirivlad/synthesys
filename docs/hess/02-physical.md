# HESS: физический интерфейс

## Сигналы (логическая модель)

| Имя | Назначение | Управление |
|---|---|---|
| `HESS_CLK` | Общая тактовая линия SPI | Только текущий разрешённый OWNER |
| `HESS_D0` | SPI MOSI / QPI IO0 | В 1-bit направлении master → slave |
| `HESS_D1` | SPI MISO / QPI IO1 | В 1-bit направлении slave → master, только выбранный TARGET |
| `HESS_D2, D3` | QPI IO2/IO3 | Резерв в P0–P3, по умолчанию Hi-Z |
| `HESS_CS_N[slot]` | Индивидуальный выбор slave | Дешифратор TARGET, активен при разрешённой транзакции |
| `HESS_GRANT_N[slot]` | Только данному слоту разрешена роль master | Дешифратор OWNER / hardware gate |
| `HESS_XFER_N` | Транзакция активна / gate CS | От текущего master через аппаратный буфер |
| `HESS_ATTN_N` | Событие/потребность в опросе CPU | Open-drain нескольких модулей |
| `HESS_RST_N` | Сброс периферии | CPU через безопасный open-drain/супервизор |
| `OWNER[3:0]` | Выбор CPU (0) / одного из слотов 1…8 | CPU/backplane logic |
| `TARGET[3:0]` | Выбор CPU (0) / одного из слотов 1…8 | CPU/backplane logic |
| `SLOT_ID[2:0]` | Физический номер слота 1…8 | Статическая разводка, не drives |

**Важно:** OWNER/TARGET — локальные управляющие сети CPU → backplane, **не обязаны идти в каждый слот**. На самом слоте доступны дешифрированные CS_N и GRANT_N. Так уменьшается количество проводов к модулям. Для CPU как адресата требуется отдельная CS/входная аппаратная логика.

## Блокировка драйверов

1. `OWNER` задаёт **ровно один** разрешённый источник CLK/MOSI/XFER; при RESET ни один периферийный драйвер не активен.
2. `TARGET` и `XFER_N` формируют **ровно один** CS_N выбранного slave; если `OWNER==TARGET` — транзакция запрещена.
3. MISO включается только у выбранного slave, когда его CS_N активен; остальные физически Hi-Z.
4. Функция `grant` аппаратно разрешает соответствующий внешний буфер, и ни один ESP32 не может напрямую обходить блокировку другим выводом.
5. CPU отключает своё состояние master во время гранта, не ломая исходящий OWNER/TARGET decode.
6. Для QPI обе стороны могут менять направление D0..D3 по фазам, поэтому потребуются дополнительные direction-гейты. **Нельзя просто использовать текущий P0-P3 SIO-драйвер для QPI.**

## Реальный монтаж с витой парой

Витая пара **не превращает SPI в дифференциальный интерфейс**. Для однотактных сигналов используйте пары `CLK–GND`, `D0–GND`, `D1–GND`, `XFER–GND`, позже `D2–GND`, `D3–GND`. Не скручивайте D0+D1 как якобы дифференциальную пару.

- Суммарная магистраль короткая, без длинных отводов/звезды; в P1 ориентир: 15–20 см как **начальный проектный бюджет**, измерениями уточнить.
- Жгут витой пары на backplane и короткие посадочные ветви; МГТФ только на платах модулей.
- 22–47 Ω резисторы в цепи драйверов **предусмотреть как footprint/сменные**, номинал уточнять по ringing на осциллографе. Это не «обязательные для всех» значения.
- Не применять типичные для CAN 120 Ω терминаторы к SPI-линии без расчёта: для 3,3 В GPIO это может перегрузить драйвер.
- Линии управления OWNER/TARGET не высокочастотные, но должны быть устойчивы к reset/glitch; использовать pull-ups/down, latch при необходимости.
- Модули без питания не должны паразитно питаться через сигнал; проверять буферы с Ioff/failsafe режимами.

## Ограничения ESP32-S3

- GPIO33–37 на модуле с Octal PSRAM R8 недоступны: https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/gpio.html
- SPI Slave — CPU-driven, есть задержки и требования к DMA/готовности: https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/spi_slave.html
- Общий CLK и расширенная роль master требуют явного переключения не только драйверов, но и pin matrix/ISR, если используем два аппаратных SPI-контроллера.
- QPI / SPI Slave HD — отдельное исследование драйвера и формата: https://docs.espressif.com/projects/esp-idf/en/stable/esp32s3/api-reference/peripherals/spi_slave_hd.html

**Ни один проектный вывод не является разрешением паять шину без теста M1/M2.**
