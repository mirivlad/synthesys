# HESS v1 — единая адресная SPI/QPI-шина

## Принцип

HESS — **одна разделяемая физическая магистраль** для небольших команд и редких прямых передач больших объёмов. Нет отдельной «служебной CAN» и нет Storage-owned второй шины. При этом координационные линии CPU (OWNER, TARGET, grant, ATTN) физически отделены от битов полезных данных и остаются доступны, пока шина занята.

## Компоненты

- CPU по умолчанию владеет правом инициировать транзакции.
- `OWNER` выбирает единственный разрешённый источник CLK/MOSI; `TARGET` выбирает отдельного адресата CS_N и MISO.
- Активный master может быть CPU или любым подключённым вычислительным модулем, поддерживающим нужный SPI PHY.
- Грант **на одну пару owner-target и ограниченное время**, не безусловное право менять адреса и обращаться ко всем устройствам.
- `ATTN_N` — общая open-drain линия событий/завершений, она не переносит данные.
- `RST_N` — управляемый безопасный сброс периферийных модулей, не reset самого CPU.
- `READY` — логическая готовность к обмену (опрос CPU и/или отдельный handshake при необходимости).

## Что точно не делаем

- Ни **общей RAM**, ни DMA в память CPU, ни раздачи кадров/PCM через HESS во время нормальной работы.
- Не подразумеваем, что CPU и Video могут одновременно передавать по одним проводникам.
- Не считаем просто выдачу GPIO `GRANT` защитой от электрического конфликта; выходы гейтятся аппаратно.
- Не считаем 4-битный QPI в slave-режиме на ESP-IDF уже доказанным.
- Не обещаем hot-swap или совместимость со старой схемой HESS v0 / HESS-C+HESS-D.

## Пяти-модульная штатная работа

При пяти активных модулях CPU должен управлять не только электрической безопасностью, но и **ограничением времени владения**. Peer-to-peer bulk transfers делятся на короткие гранты; после каждого CPU получает возможность обработать `ATTN_N` от Input, выдать команды Video/Sound и только затем продолжить bulk. Для минимальной полной системы это **обязательная способность**, не отложенный QoS. Подробно: [арбитраж](03-arbitration.md) и [приёмка](../acceptance-five-modules.md).

## Профили

| Профиль | Описание | Статус |
|---|---|---|
| HESS-P0 | SPI 1-bit, CPU master, один slave, 100 kHz | M1 |
| HESS-P1 | SPI 1-bit, CPU ↔ несколько slave, выбор TARGET | M2 |
| HESS-P2 | SPI 1-bit, master может быть периферийным, grant/Hi-Z | M3 |
| HESS-P3 | SPI 1-bit, direct block transfer, CRC, recovery | M4 |
| HESS-Q | Quad data lines (QPI), DMA, ускорение | Только исследование |

**Обратите внимание:** `P1` — название и первой перфоплатной сборки, и профиля теста; в протоколе это разные сущности. В дальнейшем можно переименовать профили в T0–T4.
