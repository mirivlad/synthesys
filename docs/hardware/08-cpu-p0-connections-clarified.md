# CPU P0 — однозначные обозначения и соединения (исправление схем)

**Ревизия 17.11.2026.** Этот документ заменяет неоднозначные стрелки прежних рисунков. Совместим с **ESP32-S3-DevKitC-1 v1.1 (J1/J3 по 22 пина)** и купленным **74HC125D SOIC-14 с переходником SOIC→DIP-14 1:1**. Расположение ножек подтверждено официальными [Espressif DevKitC-1 J1/J3](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.1.html) и [Nexperia 74HC125D SO14](https://assets.nexperia.com/documents/data-sheet/74HC_HCT125.pdf).

## Кто есть кто

| Код на чертеже | Физическая деталь |
|---|---|
| **U1** | Вся ESP32-S3-DevKitC-1 вместе с разъёмами, USB и стабилизатором |
| **U1.J1.n** | Контакт n **левого ряда** J1 непосредственно на U1 |
| **U1.J3.n** | Контакт n **правого ряда** J3 непосредственно на U1 |
| **U2** | Только логический буфер 74HC125D (четыре независимых канала в SOIC-14) |
| **U2.n** | **Ножка микросхемы** U2, n=1..14; на переходнике DIP-14 контакт n соответствует ножке n |
| **JH1.n** | Контакт n **отдельного** HESS-40 IDC 2×20 |
| **JUSB1** | Штатный нижний правый USB-порт ESP32-S3-DevKitC-1, USB Serial/JTAG |

J1 и J3 — условные имена двух **гребёнок на U1**, их **не** следует путать с JH1. Предыдущая запись вида \`GPIO4 → U2.2 → U2.3 → HESS.9\` вводила в заблуждение: **U2.2 и U2.3 никогда не соединяются прямым проводом**. Они являются входом \`1A\` и выходом \`1Y\` **логического канала внутри U2**. Когда U2.1=\`/1OE\` равен LOW, выход повторяет вход; при HIGH выход в состоянии Hi-Z.

## Какие проводники паять

Все указанные ниже маршруты — **раздельные электрические сети**. Полные соединения записаны по отдельным точкам:

| Сигнал | Провод А: от U1 на вход буфера | Внутри U2 (не провод) | Провод Б: от выхода буфера на JH1 |
|---|---|---|---|
| **CLK** | U1.J1.4 (GPIO4) → **U2.2** (1A) | канал 1, \`1A→1Y\` | **U2.3** (1Y) → **JH1.9** |
| **MOSI / D0** | U1.J1.5 (GPIO5) → **U2.5** (2A) | канал 2, \`2A→2Y\` | **U2.6** (2Y) → **JH1.11** |
| **XFER_OUT_N** | U1.J1.15 (GPIO9) → **U2.9** (3A) | канал 3, \`3A→3Y\` | **U2.8** (3Y) → **JH1.19** |

Проводники, **не проходящие через U2**:

| U1 DevKit контакт | GPIO / статус | Другой конец |
|---|---|---|
| J1.6 | GPIO6 / MISO input | JH1.13 |
| J1.16 | GPIO10 / CTRL_SER | JH1.37, **только CPU-разъём** |
| J1.17 | GPIO11 / CTRL_SCK | JH1.38, **только CPU-разъём** |
| J1.18 | GPIO12 / CTRL_LATCH | JH1.39, **только CPU-разъём** |
| J1.19 | GPIO13 / BUS_ENABLE | JH1.40, **в P0 LOW**, аппаратная подтяжка 10 кОм к GND на backplane |
| J1.20 | GPIO14 / ATTN_N input | JH1.25; на backplane только один pull-up к 3,3 В |
| J1.1 | +3,3 В | U2.14 и U2.13, один конец R1 и C1 |
| J1.22 | GND | U2.7, U2.12, второй конец C1, общий GND JH1 |

**Питание и /OE (НЕ подключать к GND до проверки арбитра):**
- U2.14 (\`VCC\`) → 3,3 В от U1.J1.1.
- U2.7 (\`GND\`) → U1.J1.22.
- C1 100 нФ между U2.14 и U2.7, непосредственно возле микросхемы.
- U2.1 (\`/1OE\`), U2.4 (\`/2OE\`), U2.10 (\`/3OE\`) соединить **между собой в сеть /CPU_OE**.
- R1 10 кОм соединяет **/CPU_OE с 3,3 В**, чтобы выходы U2.3, U2.6, U2.8 гарантированно были Hi-Z при разработке P0.
- U2.13 (\`/4OE\`) → 3,3 В; U2.12 (\`4A\`) → GND; U2.11 (\`4Y\`) оставить неподключённым.

**Порт ПК:** Используется штатный USB Serial/JTAG DevKit, соединение внутри U1 (GPIO19 D− / GPIO20 D+), внешние проводники от USB к JH1 **не требуются**.

## Состояние P0 и безопасность

**На P0 U2 намеренно отключён от HESS** через высокий /OE. Так можно безопасно проверить сам CPU USB-monitor, но **нельзя считать, что CPU уже способен посылать SPI-пакеты в Storage**. Для P1 нужна проверенная электрическая схема grant/Hi-Z/break-before-make с дешифратором владельца. Нельзя просто притянуть /OE к GND, когда на шине есть другие потенциальные ведущие.

Питание +5 В из контактов **JH1.1, JH1.2, JH1.5, JH1.6** при USB-подключении CPU **НЕ СОЕДИНЯТЬ** с 5V на U1: пока отсутствует проверенная развязка VBUS/внешнего питания. GND общий. Сначала прозвонить SOIC→DIP переходник и проверить его нумерацию **сверху со стороны ключа**, а не зеркально со стороны пайки.
